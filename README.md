# SRE KPI Generator

A deterministic KPI generation tool for SRE/NOC shift reporting. Upload an Excel or CSV shift report and instantly get formatted KPI tables — Overall Shift KPIs and Customer-wise Shift KPIs — ready to copy into Outlook or export.

**No AI. No guesswork. Same input always produces the same output.**

---

## Features

- Upload `.xlsx`, `.xls`, or `.csv` shift reports
- Generates Overall Shift KPIs and Customer-wise Shift KPIs
- MTTA / MTTR calculated per incident, averaged per severity
- SLA breach detection with configurable thresholds
- Copy tables directly to clipboard — pastes as a formatted table in Outlook
- Export to CSV, Excel, or PNG
- Shift filter (Day / Night) and date range filter
- Report header (shift name, date, engineer on duty)
- Shift history — last 20 reports saved in the browser
- Light and dark theme
- Single `npm start` — no separate backend process

## Getting Started

### 1. Clone the repo

```bash
git clone https://github.com/YOUR_USERNAME/sre-kpi-generator.git
cd sre-kpi-generator
```

### 2. Install dependencies

```bash
npm install
```

### 3. Build the frontend

```bash
npm run build
```

### 4. Start the server

```bash
npm start
```

Open **http://localhost:3000** in your browser.

## Development mode

If you want live frontend reloading while working on the UI, run both in separate terminals:

```bash
# Terminal 1 — API server
node src/server/index.js

# Terminal 2 — Vite dev server (hot reload)
npx vite --config vite.config.js
```

Then open **http://localhost:5173** (Vite proxies API calls to port 3000 automatically).

## Input Format

The uploaded Excel/CSV file must contain these columns:

| Column | Example |
|--------|---------|
| Team Name | DUVE |
| Counter ID | duve-3428 |
| Message | Alert fired |
| Severity | sev1 / sev2 |
| Status | RES |
| Source | Grafana |
| Created (IST) | 2026-05-09 21:29:00 |
| ACK At (IST) | 2026-05-09 21:29:20 |
| Resolved At (IST) | 2026-05-09 21:56:00 |
| Notes | (optional) |

**Severity values processed:** `sev1`, `sev2`, `p1`, `p2`
All other severity values (blank, sev3, unknown) are silently skipped.

---

## KPI Logic

| Metric | Formula |
|--------|---------|
| MTTA | `ACK At − Created` |
| MTTR | `Resolved At − Created` |
| Avg MTTA | `Sum(MTTA) / incident count` per severity |
| Avg MTTR | `Sum(MTTR) / incident count` per severity |
| IMR breach | `MTTR > SLA threshold` |

**Default SLA thresholds:**
- Severity 1 → 5 minutes
- Severity 2 → 10 minutes

Thresholds are configurable in the Settings page — changes take effect immediately without a restart.

## Deployment

### Railway (recommended)

1. Push to GitHub
2. Go to [railway.app](https://railway.app) → New Project → Deploy from GitHub
3. Set build command: `npm install && npm run build`
4. Set start command: `node src/server/index.js`
5. Done — Railway provides a public URL

### Render

1. Push to GitHub
2. Go to [render.com](https://render.com) → New Web Service
3. Build command: `npm install && npm run build`
4. Start command: `node src/server/index.js`

### Vercel

A `vercel.json` and `api/index.js` are included. Run:

```bash
npm install -g vercel
vercel --prod
```

> Note: On Vercel, SLA threshold settings reset on cold starts since there is no persistent storage. KPI calculations are always correct.

---

## Notes

- Uploaded files are processed in memory and never saved to disk
- Shift history is stored in the browser's `localStorage` — it is per-browser and not shared across team members
- The KPI engine is fully deterministic — the same file always produces the same output
